# Componenta HTTP Body Parsing Middleware

PSR-15 промежуточный обработчик для разбора тела HTTP-запроса в разобранное тело и загруженные файлы PSR-7 запроса. Поддерживает JSON, `application/x-www-form-urlencoded` и `multipart/form-data`.

Используйте пакет в HTTP-приложениях, которым нужен разбор тела для методов и типов содержимого, которые PHP не разбирает нативно.

## Установка

Требуется PHP 8.4+ с расширениями mbstring и ctype. Провайдер совместим по ограничению Composer с Config 3 и 4.

```bash
composer require componenta/http-body-parsing-middleware
```

Пакет публикует `Componenta\Http\Middleware\BodyParsingConfigProvider` через метаданные Composer.

## Конфигурация

Провайдер регистрирует `BodyParsingMiddleware` из:

- `StreamFactoryInterface`
- `UploadedFileFactoryInterface`
- `ResponseFactoryInterface`

Установите один интеграционный пакет PSR-7/PSR-17, чтобы эти фабрики были в контейнере.

## Поведение

Промежуточный обработчик пропускает запрос, если:

- `getParsedBody()` уже установлен;
- метод равен `GET`, `HEAD`, `OPTIONS` или `TRACE`;
- multipart-файлы уже присутствуют в запросе PSR-7.

Для совместимости скалярные JSON-значения сохраняются в ключе `__scalar`. Атрибут `BodyParsingMiddleware::ATTR_JSON_KIND` различает `scalar`, `object` и `array`. Целые числа за пределами диапазона PHP int преобразуются в строки.

Имена multipart-полей и загрузок нормализуются по правилам PHP: ведущие пробелы удаляются, точки и пробелы в корневом имени заменяются подчёркиваниями. Вложенные ключи сохраняют исходное написание.

После установки зависимостей разработки тесты пакета запускаются командой `composer test`.

## Основные классы

- `BodyParsingMiddleware` является PSR-15 промежуточным обработчиком.
- `Body\MultipartParser` разбирает multipart-тело.
- `Body\MultipartPart` представляет одну multipart-часть.

## Связанные пакеты

- [`componenta/http-psr`](../http-psr/README.ru.md) связывает создание серверного запроса.
- [`componenta/app-http`](../app-http/README.ru.md) запускает HTTP-промежуточные обработчики.

## Ограничения и ошибки

`BodyParsingLimits` задаёт максимальный размер тела (по умолчанию 8 МиБ), части, количество частей/полей, размер заголовков и глубину вложенности. Тело считывается ограниченными порциями, но пока буферизуется в памяти. Устанавливайте независимые транспортные ограничения. Позиция перематываемого потока восстанавливается; неперематываемый поток при успешном разборе заменяется эквивалентным буфером. Входной поток должен содержать тело с начала.

Некорректные данные приводят к `BodyParsingException` со статусом 400, превышение ограничений — 413. Передача `responseFactory:` преобразует исключения в ответы; провайдер конфигурации передаёт фабрику автоматически. Несколько файлов с одним именем сохраняются в списке. Неполный multipart и неоднозначные параметры заголовков отклоняются. Bare LF, устаревшие кодировки передачи и расширенные имена файлов поддерживаются для совместимости. Имя и тип загруженного файла остаются недоверенными метаданными.
